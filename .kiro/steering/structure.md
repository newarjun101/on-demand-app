# Repository Structure

TypeScript monorepo with one shared backend and three independent React/Vite frontends. There is no shared workspace package and no cross-imports between frontends.

```text
on-demand-app/
├── backend/                 Express + Prisma + Socket.IO API (port 4000)
├── customer-web/            Customer marketplace (port 5173)
├── worker-web/              Worker portal (port 5174)
├── admin-web/               Admin portal (port 5176)
├── docs/PROJECT_KNOWLEDGE.md  Implementation map (read before non-trivial changes)
├── .ai/                     Shared AI project memory (see memory.md)
├── .kiro/steering/          Kiro steering files (this folder)
├── AGENTS.md                Repository agent guide and rules
├── README.md                Setup, demo accounts, ports, commands
└── docker-compose.yml       postgres (5433), backend, and the three web apps
```

## backend/

```text
backend/
├── prisma/                  schema.prisma (authoritative models), migrations/ (8, ordered), seed.ts
├── scripts/                 generate-avatars.js, generate-portfolio.js (demo assets)
├── postman-collection.json  generated by `npm --prefix backend run postman`
└── src/
    ├── server.ts            HTTP + Socket.IO startup
    ├── app.ts               buildApp(): middleware and dual-prefix router mounting
    ├── config/              env.ts (all env vars), prisma.ts, redis.ts (lazy, optional)
    ├── middleware/          auth (detectOrigin, JWT, role/permission), i18n (apiVersionRouter,
    │                        notFoundHandler, errorHandler), rateLimit, upload (Multer), validate (Zod)
    ├── routes/              17 route files: path registration, guards, validation
    ├── controllers/         17 controllers: req/res orchestration only
    ├── services/            19 services: business rules, transactions, notifications, socket emits
    ├── repositories/        file.repository.ts only
    ├── validators/          10 Zod schema modules
    ├── sockets/io.ts        initSockets, emitToUser, emitToUsers, emitToApp
    ├── utils/               api.ts (shared response helpers), geo, jwt, money, password
    ├── scripts/             postman.ts (Postman collection generator)
    └── swagger.ts           OpenAPI spec (must match every mounted route)
```

Request flow: `route -> middleware -> controller -> service -> Prisma/repository -> response helper (utils/api.ts)`.

## Frontends (same layout in all three)

```text
<app>/
├── index.html, vite.config.ts, tailwind.config.js, postcss.config.js, tsconfig*.json
├── Dockerfile, nginx.conf   Static build served by nginx on port 80 in the container
└── src/
    ├── main.tsx -> App.tsx  Routes (and guards)
    ├── app/AppProviders.tsx React Query, i18n, auth, toast, validation translation
    ├── api/client.ts        Axios, Authorization + X-App-Origin, 401 refresh queue
    ├── api/endpoints.ts     Endpoint functions
    ├── contexts/AuthContext.tsx
    ├── layouts/             App chrome plus route outlet
    ├── components/          UI primitives (UI.tsx), Pagination, LocaleSwitcher, modals, etc.
    ├── pages/               Route-level screens
    ├── hooks/, services/    customer-web and worker-web only: useSocket.ts, socket.ts
    ├── i18n/                index.tsx plus locales/{en,zh,my,th,hi}.json
    └── utils/
```

| App | Key files |
| --- | --- |
| `customer-web` | `components/CustomerHeader.tsx` (top nav `md+`, bottom nav on phones), `layouts/CustomerLayout.tsx`, `components/WorkerCard.tsx`, `PaymentModal.tsx`, `ReviewModal.tsx` |
| `worker-web` | `components/WorkerHeader.tsx` (top nav `md+`, bottom nav on phones, online/offline toggle), `layouts/WorkerLayout.tsx`, approval guard `requireApproved` in `App.tsx`, `pages/OnboardingPage.tsx` |
| `admin-web` | `layouts/AdminLayout.tsx` (sidebar drawer below `lg`, collapsible sidebar from `lg`), `contexts/AuthContext.tsx` (permission checks), `pages/` including `RolesPage`, `KycPage`, `AuditPage`. No socket client. |

Client identity: each app sends its own `X-App-Origin` (`CUSTOMER_WEB`, `WORKER_WEB`, `ADMIN_WEB`) and stores tokens under its own keys (`lsm_customer_access_token`, `lsm_worker_access_token`, `lsm_admin_access_token`).

## Where to Start for a Task

| Task | Start with |
| --- | --- |
| API endpoint or contract | `backend/src/routes/`, `validators/`, `controllers/`, `services/`, then `swagger.ts` |
| Database model or state | `backend/prisma/schema.prisma`, the matching service, new migration |
| Customer behavior | `customer-web/src/App.tsx`, then page, API and locale files |
| Worker behavior | `worker-web/src/App.tsx`, approval guard, then page, API and locale files |
| Administration | `backend/src/routes/admin.routes.ts`, `admin.service.ts`, then `admin-web` |
| Realtime | `backend/src/sockets/io.ts`, the emitting service, client `useSocket` hook |
| Deployment | `docker-compose.yml`, Dockerfiles, nginx files, root `README.md` |
| UI layout or responsiveness | each app's `layouts/`, `components/UI.tsx`, then the page |

## Layout Files That Control Responsive Behavior

- `admin-web/src/layouts/AdminLayout.tsx`: sidebar drawer (mobile) and collapsible sidebar (desktop)
- `customer-web/src/components/CustomerHeader.tsx`: top nav (`md+`) and bottom nav (mobile)
- `worker-web/src/components/WorkerHeader.tsx`: top nav (`md+`) and bottom nav (mobile)
- Each app's `src/components/UI.tsx` holds shared primitives (Button, Card, Input). Fix responsiveness there before patching individual pages.

## Rules That Shape the Structure

- Keep route registration and middleware in `routes/`, HTTP orchestration in `controllers/`, business rules in `services/`, persistence in `repositories/` and `config/`.
- Every API router is mounted at both `/api/*` and `/api/v1/:locale/*`. Change both or neither.
- Never import across `customer-web`, `worker-web`, `admin-web`.
- Add user-facing text to all five locale files of every frontend that renders it.
- Do not edit an applied Prisma migration. Add a new one.
